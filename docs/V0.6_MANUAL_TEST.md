# Eye of Zomm v0.6 — Windows acceptance test

Use this on the packaged Windows installer with a normal EverQuest Legends installation. It is intentionally short enough to run before publishing, while covering the local game files that repository tests cannot contain.

Record the app version, Windows version/scaling, selected EQ root, active character log, and pass/fail for each section. Do not attach an unredacted log or filesystem path to a public issue.

## 1. Install and first run

1. Install `EQLWiki-Eye-of-Zomm-Setup-0.6.0-x64.exe`.
2. Launch with a fresh Eye of Zomm profile.
3. Choose the EverQuest root, normally `C:\EverQuest Legends`, once.
4. Confirm Settings shows that root and the most recently modified `Logs\eqlog_*.txt`.
5. Restart and confirm no folder picker appears and automatic mode follows the newest log.
6. Choose a specific log in Settings, restart, then choose **Use newest log** and verify automatic mode returns.

Pass: setup takes one folder choice; Folder and Log readiness are correct; no valid folder is described as missing.

## 2. Signed coordinates, floors, and camera

1. Enter Befallen and generate a `/loc` line at or near `Your Location is -30, -961, -66`.
2. Confirm Eye of Zomm displays `/loc -30.00, -961.00, -66.00`, matching game chat, while the internal client `.txt` map anchor is X `961`, Y `30`, Z `-66`.
3. Confirm the player marker is in the same room as the in-game map and on the floor near Z `-66`, not the stacked floor near `-37`.
4. Test **First**, **Top**, and **Map**. Confirm all three center on the same signed location and the overlay initially shows all floors.
5. Move in a clear direction, generate another `/loc`, and confirm First Person/minimap face the movement trajectory while the selected presentation remains unchanged.

Pass: logged Y,X,Z becomes canonical world X,Y,Z; the explicit client-map projection applies `(-world X, -world Y, world Z)` without swapping; both reach the same viewer anchor with no stacked-floor jump.

## 3. Zone textures

1. Load one indoor S3D zone and one outdoor S3D zone after installing v0.6.
2. Wait for the zone to rebuild; v0.6 invalidates the previous parsed-zone cache.
3. Compare prominent walls, floors, and landmarks with the game in First/Top. Map Overlay is intentionally client `.txt` line art and is not a texture test.
4. In a zone with animated material frames, watch long enough to verify the material remains textured rather than flashing to a placeholder.

Pass: known bitmap-backed materials are not replaced by widespread flat gray/white surfaces. Capture the zone short name and a screenshot for any mismatch.

## 4. Persistent navigation

1. In Befallen, place the player with `/loc` and choose Baron Telyx V’Zher from **Navigate to** or a **Path** action.
2. Confirm the destination is marked and the route bar says one of: path plus distance, marker only, or a specific missing-coordinate error.
3. If a path is produced, visually confirm it stays in corridors, does not cross walls, and does not fall through the upper floor.
4. Move at least eight units and generate `/loc` again. Confirm the same destination remains selected and the path updates automatically.
5. Switch First/Top/Map and enter/leave Minimal. Confirm the destination and selected map presentation survive.
6. Select an explicit floor filter, generate `/loc`, and confirm that same-zone re-routing does not clear the filter.
7. Press **Clear** and confirm both path and destination are removed.

Pass: route state is explicit and persistent. Current graph routing permits an exposed downward edge and an upward step no greater than +6 Z; it must not claim a route when collision validation fails.

## 5. Consider loot tray

1. With the game foregrounded, consider a mob that produces:
   `Soldier of V Zher - a rare creature - scowls at you, ready to attack -- looks like quite a gamble. (Lvl: 26)`
2. Confirm a bottom-docked tray opens without bringing Eye of Zomm to the foreground.
3. Confirm name, level, con, known drops, **My Class**, **Path**, and close controls.
4. Hover/focus the tray for more than 16 seconds; it should remain. Leave it and confirm it closes after the grace period.
5. Hover or keyboard-focus a drop and confirm its Itembox detail appears.

Pass: the exact Legends descriptor is recognized, the clean NPC name is used, and the tray never covers the full navigation rail.

## 6. Items and Itembox details

1. Detect or select MNK while in Befallen, then open Items with an empty query.
2. Confirm the scope line says Befallen/MNK and useful equipment appears before potions. `Enchanted Fine Steel Morning Star` is the current production-pack leading regression result.
3. Exercise Slot, Sort, class, era, Current zone, a global query, and **Reset**. Confirm deliberate filters override the default and Reset restores contextual browsing.
4. Hover an item at Base, then set a nonzero Item tier and inspect it again. Confirm adjusted values are labeled and changed stats show their base value in parentheses.
5. Keyboard-focus an item name, verify the tooltip, and press Escape.

Pass: current-zone/class results are useful without a query, controls agree with the scope line, icons load where present, and tier values agree between card and tooltip.

## 7. Window, search, combat, and drops

1. Type into **Search EQLWiki** with mouse and with Ctrl+K; press Enter and verify an EQLWiki `Special:Search` page opens.
2. Toggle **Pin to top**. Confirm the custom draggable titlebar disappears, the app remains above the game, and its taskbar button remains.
3. Enter Minimal. Confirm First/Top/Map, route controls, current-fight DPS, mob list, and Pin/Full controls remain. Exercise **Hide intel** and restore it.
4. Generate two combat chunks separated by more than the configured quiet period. Confirm two encounters named for the first attacked NPC plus timestamp.
5. Loot a logged item and confirm Drops shows item, quantity, NPC/source, zone, time, and observed drops/kills evidence.

Pass: no routine action opens a focus-stealing alert, window controls remain reachable, and observed percentages are not presented as authoritative wiki rates.

## Release decision

Do not publish if any of these fail: folder/log truth, signed coordinates, correct floor, map mode persistence, widespread texture resolution, consider tray, input into Search EQLWiki, or Windows packaging. A route failure caused by missing destination/collision data may ship only when the destination marker and reason are clear and no invalid path is displayed.
