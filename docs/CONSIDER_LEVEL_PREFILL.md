# Level evidence from the selected log

A real monster kill may prefill the contribution draft's Level from explicit
`(Lvl: N)` consider output earlier in the same continuous zone visit. The field
starts unconfirmed. Its local evidence records the consider time and observed
level; no consider alone creates a contribution, population proposal, or prompt.
Intel continues receiving considers independently of contribution ignores.

The parser anchors the selected character from the selected log filename.
Other players' `/who` rows never move the current zone. A self `/who` row can
provide the readable zone name and client short name. Exact catalog aliases are
used when available; an unknown short name never replaces a readable display
name, and zone-name substrings do not establish a log identity.

Every explicit `You have entered` line starts a new visit, including reentering
the same named zone. A different numeric instance ID in a self `/who` row also
starts a new visit. An ordinary same-zone `/who` refresh retains the current
visit. Source switches, truncation, and discontinuities discard prior context.
Consider proof keeps an unknown normal/raid designation unknown. This feature
does not change automatic loot publication's existing instance policy.

On startup or source reset, a cancellable native worker streams the selected
file's prefix before the initial tail. It restores only bounded zone and
numeric-consider metadata. The renderer and native log witness seed that
context before parsing the tail. Historical kills and loot never become fresh
contribution events. Source-generation checks discard superseded worker
results; replacing the selected file also invalidates the result. The worker
retains no chat or raw surrounding lines, and no log path enters level proof.

At most 512 targets and 16 observations per target are retained. Readings expire
after six hours and cannot cross a visit boundary. Prefix recovery has an
eight-second deadline; unavailable context leaves the level unfilled. Matching
uses exact normalized NPC names or verified canonical catalog aliases, never
name prefixes, NPC families, or the player's relative con color. Ambiguous
canonical identities provide no prefill.

If several numeric levels were observed for one exact NPC name, the draft uses
the observed minimum–maximum and retains the latest reading in its provenance.
This is an observed range from that visit, not proof of the NPC's complete
spawn-level range. Existing contributor edits or confirmed levels win over
subsequent log observations.

Verification covers parser/queue admission and scope, worker recovery from
before the initial tail, source-generation cancellation, and the actual worker
to Chromium editable contribution form. All fixtures use synthetic logs and
isolated profiles. Read-only testing of the selected local log observed prefix
recovery in about 57 ms for a 12.5 MB file; this is a local observation, not a
latency guarantee for larger files.
